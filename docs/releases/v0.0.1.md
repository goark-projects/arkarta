# Arkarta v0.0.1 Release Notes

Language: English | [简体中文](v0.0.1.zh-CN.md)

Release date: 2026-08-27  
Module: `goark.dev/arkarta`  
License: Apache License 2.0

## Summary

`v0.0.1` is the first public Arkarta release. It establishes the Goark enterprise Web standard baseline for Servlet-style containers and the upper Web development stack.

This release is a standards baseline, not a production Web container. Goark Tomcat, Goark Jetty, and high-performance native containers should implement this module and prove compatibility through the Arkarta TCKs.

## Install

```shell
go get goark.dev/arkarta@v0.0.1
```

## What Is Included

### Servlet Standard

- Core request and response contracts.
- Handler, Servlet, Filter, Chain, WebApp, lifecycle, dispatch, and error semantics.
- Servlet path mapping, RequestDispatcher, error pages, and panic recovery.
- `net/http` adapter and minimal reference container.
- Container SPI and dynamic registration metadata.
- Optional profiles for Session, Multipart, Async/Stream, Upgrade, Native I/O, and Servlet declarative security.
- Servlet TCK entry points for Core and supported profiles.

### WebSocket Standard

- RFC 6455 handshake and frame layer.
- Subprotocol negotiation.
- permessage-deflate negotiation.
- Endpoint, session, message, close status, connection SPI, and service loop.
- Servlet Upgrade adapter with HTTP 101 writer, frame connection adapter, and endpoint helper.
- WebSocket TCK for handshake, endpoint lifecycle, compression, and frame codec.

### JSON Standard

- `json.Codec`, streaming encoder, and streaming decoder contracts.
- bytedance sonic as the single built-in implementation.
- `json/sonic` compatibility entrypoint.
- Input size limit, unknown-field gate, number precision mode, HTML escaping, and indentation controls.
- `json/tck` compatibility tests for codec implementations.

### Validation Standard

- Struct-tag field validation.
- Nested struct and slice validation.
- Validation groups through `arkarta-groups`.
- Message resolver.
- Object-level constraints.
- Built-in constraints: `required`, `notblank`, `min`, `max`, `len`, `email`, `oneof`, `regexp`, `url`, `uuid`, `gt`, `gte`, `lt`, `lte`, `contains`, `startswith`, and `endswith`.
- Custom constraints and aggregated validation errors.

### Web MVC/REST Layer

- Method routing and path variables.
- Route groups and group-scoped interceptors.
- Automatic `HEAD` for `GET`.
- Automatic `OPTIONS` with stable `Allow`.
- JSON, form, multipart, path, query, header, and cookie binding helpers.
- Parameter conversion helpers.
- Unified `Result`, error mapper, response advice, and interceptor chain.
- `web/tck` compatibility tests.

### Root Security Contracts

- Principal and Authority.
- Authentication and Credential.
- AuthenticationManager.
- SecurityContext propagation through `context.Context`.
- Authorizer and authorization decisions.

## Compatibility and Verification

The release was prepared with:

```shell
go test ./...
go test -race ./...
go vet ./...
git diff --check
gofmt -l .
```

`gofmt -l .` must produce no output.

Container implementations should run only the TCKs for the profiles they claim:

- `servlet/tck`
- `web/tck`
- `websocket/tck`
- `json/tck`

## Not Included

- Goark Tomcat, Goark Jetty, or any production Web container.
- Java namespace compatibility with `jakarta.servlet` or `javax.servlet`.
- JSP, JSTL, Expression Language, WAR/EAR packaging, Java annotations, runtime classpath scanning, or Java-style inheritance APIs.
- OAuth2/OIDC/JWT providers, CSRF, CORS, password storage, or policy engines. Those belong to higher-level security implementations.

## Release Scope

`v0.0.1` is a preview baseline. Public APIs are designed as standards, but necessary source-incompatible corrections may still happen before `v0.1.0` if required for standard quality.
