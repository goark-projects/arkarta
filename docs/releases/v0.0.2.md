# Arkarta v0.0.2 Release Notes

Language: English | [简体中文](v0.0.2.zh-CN.md)

Release date: 2026-09-03
Module: `goark.dev/arkarta`
License: Apache License 2.0

## Summary

`v0.0.2` establishes a transport-neutral Servlet boundary. Hertz, `net/http`, and future native containers can now implement the same Arkarta request, response, cookie, upgrade, and TCK contracts without importing transport-specific types into the standard.

Arkarta remains the standard and compatibility-test module. Production containers, including Arkhos, remain independently replaceable implementations.

## Install

```shell
go get goark.dev/arkarta@v0.0.2
```

## Highlights

### Transport-Neutral Servlet Contracts

- Added the `servlet.Header` interface and independent in-memory header implementation.
- Added `servlet.RequestInput` so native containers can construct requests without synthesizing `http.Request`.
- Added Arkarta-owned `servlet.Cookie` parsing and serialization contracts.
- Added request mutation methods for method, scheme, host, remote address, and body replacement.
- Decoupled response headers, multipart parsing, Basic authentication, and WebSocket integration from concrete `net/http` types.
- Retained `servlet/nethttp` as the reference implementation and interoperability path.

### Container SPI and TCK

- Added transport-neutral TCK request, response, and Driver contracts.
- Added the `servlet/tck/nethttp` reference driver.
- Added the Upgrade container profile.
- Added a transport-neutral WebSocket handshake entry point.
- Container implementations must continue to claim only the profiles backed by their own passing TCK runs.

### Request Correctness and Lifecycle

- URL-encoded form parsing now reads transport-neutral request bodies correctly.
- The form body limit is configurable through `servlet.WithMaxFormBodySize`; its safe default is 10 MiB.
- Request options flow through the `net/http` adapter.
- Context paths are carried directly in request input to avoid repeated derivation on the hot path.
- Async completion waits for worker quiescence.
- The default servlet participates in application lifecycle.

### JSON and Validation

- bytedance sonic is now the single built-in Arkarta JSON implementation.
- `json.NewCodec` and `json.NewSonicCodec` create the supported codec.
- Web validation groups are available to routing and binding integrations.

## Compatibility Notes

Arkarta is still in the `v0.0.x` preview series. This release contains necessary source-incompatible corrections to make the standard implementable by native containers:

- `Request.Header()` and `Response.Header()` return `servlet.Header` instead of `http.Header`.
- Request cookies use `servlet.Cookie`; missing cookies return `servlet.ErrNoCookie`.
- `json.StandardCodec` and `json.NewStandardCodec` were removed. Use `json.NewCodec` or `json.NewSonicCodec`.
- TCK consumers should migrate transport integration to the new Driver contracts and use `servlet/tck/nethttp` for the standard-library reference path.

Applications using only Goark Web APIs should receive these changes through their container and starter dependencies. Container implementations must adapt their native request and response bridges.

## Compatibility and Verification

The release is verified with:

```shell
GOWORK=off go test ./...
GOWORK=off go test -race ./...
GOWORK=off go vet ./...
go mod verify
git diff --check
gofmt -l .
```

The Arkarta GitHub Actions workflow runs formatting, vet, tests, and race tests on Go 1.25.x. `gofmt -l .` must produce no output.

## Release Scope

- Arkarta defines Go-native standard contracts and executable compatibility tests.
- Arkarta does not claim Java namespace compatibility with `jakarta.servlet` or `javax.servlet`.
- Concrete production containers and boot starters are versioned and released separately.
- Public APIs may still receive necessary source-incompatible corrections before `v0.1.0`; those changes must be documented explicitly.
