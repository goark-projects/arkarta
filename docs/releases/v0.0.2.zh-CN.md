# Arkarta v0.0.2 发版说明

语言：[English](v0.0.2.md) | 简体中文

发布日期：2026-09-03  
模块：`goark.dev/arkarta`  
许可证：Apache License 2.0

## 摘要

`v0.0.2` 确立传输层中立的 Servlet 边界。Hertz、`net/http` 以及未来的原生容器可以实现同一套 Arkarta Request、Response、Cookie、Upgrade 和 TCK 契约，标准层不再引入具体传输实现类型。

Arkarta 继续只负责标准和兼容性测试。包括 Arkhos 在内的生产容器仍是可以独立替换的实现模块。

## 安装

```shell
go get goark.dev/arkarta@v0.0.2
```

## 主要变化

### 传输层中立 Servlet 契约

- 新增 `servlet.Header` 接口和独立内存 Header 实现。
- 新增 `servlet.RequestInput`，原生容器无需构造 `http.Request` 即可创建请求。
- 新增 Arkarta 自有的 `servlet.Cookie` 解析和序列化契约。
- 新增 Method、Scheme、Host、Remote Address 和 Body 的 Request 修改方法。
- Response Header、Multipart 解析、Basic 认证和 WebSocket 集成不再依赖具体 `net/http` 类型。
- 保留 `servlet/nethttp`，作为参考实现和标准库互操作路径。

### Container SPI 与 TCK

- 新增传输层中立的 TCK Request、Response 和 Driver 契约。
- 新增 `servlet/tck/nethttp` 参考 Driver。
- 新增 Upgrade 容器 Profile。
- 新增传输层中立 WebSocket 握手入口。
- 容器实现仍只能声明自身已经通过对应 TCK 的 Profile。

### 请求正确性与生命周期

- URL 编码表单可以从传输层中立请求体正确解析。
- 表单体上限可通过 `servlet.WithMaxFormBodySize` 配置，安全默认值为 10 MiB。
- Request Options 可以透传到 `net/http` 适配器。
- Context Path 直接包含在请求输入中，避免在请求热路径重复推导。
- Async 完成时会等待工作协程完全退出。
- Default Servlet 参与应用生命周期。

### JSON 与 Validation

- bytedance sonic 成为 Arkarta 唯一内置 JSON 实现。
- 使用 `json.NewCodec` 或 `json.NewSonicCodec` 创建受支持的 Codec。
- Web 路由和绑定集成支持 Validation Groups。

## 兼容性说明

Arkarta 仍处于 `v0.0.x` 预览阶段。本版本包含为保证原生容器可实现性所必需的源码不兼容修正：

- `Request.Header()` 和 `Response.Header()` 返回 `servlet.Header`，不再返回 `http.Header`。
- 请求 Cookie 使用 `servlet.Cookie`，Cookie 缺失时返回 `servlet.ErrNoCookie`。
- 删除 `json.StandardCodec` 和 `json.NewStandardCodec`，请改用 `json.NewCodec` 或 `json.NewSonicCodec`。
- TCK 使用方应迁移到新的 Driver 契约；标准库参考路径使用 `servlet/tck/nethttp`。

只使用 Goark Web API 的应用通常会通过容器和 Starter 依赖获得这些变化。容器实现必须适配自身的原生 Request 和 Response 桥接层。

## 兼容性与验证

本版本使用以下门禁验证：

```shell
GOWORK=off go test ./...
GOWORK=off go test -race ./...
GOWORK=off go vet ./...
go mod verify
git diff --check
gofmt -l .
```

Arkarta GitHub Actions 使用 Go 1.25.x 执行格式检查、vet、测试和 race 测试。`gofmt -l .` 必须无输出。

## 发布范围

- Arkarta 定义 Go 化标准契约和可执行兼容性测试。
- Arkarta 不声明与 `jakarta.servlet` 或 `javax.servlet` Java 命名空间兼容。
- 具体生产容器和 Boot Starter 独立维护版本并单独发布。
- `v0.1.0` 前仍允许必要的源码不兼容修正，但必须明确记录迁移方式。
